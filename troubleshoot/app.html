Windows APP 故障

Windows APP 故障 ​

「欲蓝财务魔方 APP」跑在 Windows 服务器上，接收网站端的建号命令。自 v1.3.0 起交付的是Python 版打包的单文件 exe（自带 Python 3.11 运行时，免环境）；旧版 Go exe 已不建议继续使用。排障时先看 /api/v1/health 的 version 确认版本。

接口：GET /api/v1/health 探活、POST /api/v1/create-user 建号、POST /api/v1/update-user 改号，鉴权为 Authorization: Bearer {token}。用法见 Windows APP。

启动即退出 / 提示需要管理员 ​

APP 必须在管理员账户下运行。各版本判定方式：

  • v1.3.0（Python 版打包，推荐）：内嵌 UAC 提权清单，双击自动请求提权；管理员判定用 IsUserAnAdmin + CheckTokenMembership（Administrators 组）多重判定，域账户 / runas / 计划任务 / 关闭 UAC / 内置 Administrator 都能正确识别，不会再误判。
  • 旧 Go 版 v1.2.0 及更早：只认 IsElevated（UAC 提权令牌），在域账户、runas、计划任务、关闭 UAC、内置 Administrator 等场景会误判——明明是管理员账号却提示「不是管理员」并闪退。这就是闪退的根因，直接换 v1.3.0 即可解决。

处理：

  • 先确认版本：/api/v1/health 的 version 应为 1.3.0。若仍是 Go 版 / 1.2.x 且闪退，去 APP 仓库 Release 下载 v1.3.0 的 yulan_cube_app.exe 覆盖即可（配置不用改）。
  • 双击 exe 后在 UAC 窗口点「是」；或右键 run_as_admin.bat →「以管理员身份运行」。
  • 做成计划任务 / 服务时，勾选「使用最高权限运行」，且运行账号要是管理员。
  • v1.3 已修复英文 Windows 下中文输出编码崩溃导致的闪退。
  • 若确认是管理员账号仍被拒（极特殊的域策略），命令行加 --allow-non-admin 可临时跳过检查排查；建号命令本身仍受系统权限约束，权限不足会在日志里报 net 失败。

日志隔离也是刻意设计：日志目录 ACL 只授权 SYSTEM 与 Administrators，普通用户完全看不到运行日志，避免账号与口令泄露。

提示「配置文件里的 token 为空或仍是占位值」 ​

yulan_cube_config.json 里的 token 没改。APP 会拒绝以占位口令启动，避免裸奔。

这个 token 必须与网站后台「欲蓝服务器」里填的口令完全一致（商品级配置优先，留空才回退全局）。两边任意一个改了，另一个没跟上，就会鉴权失败。

配置字段一览：

字段作用
listen_host / listen_port监听地址与端口
tokenBearer 口令，与网站后台一致
default_role默认角色 user / admin
admin_products走管理员角色的商品 ID 列表
admin_group_name / rdp_group_name管理员组 / 远程桌面组名（中文系统可按需改）
server_ip交付页展示的连接地址
use_powershellnet 命令受限时改用 PowerShell

网站侧报「无法连接欲蓝 APP」 ​

先在 Windows 机器上本地探活：

bash
curl http://127.0.0.1:端口/api/v1/health

本地通、网站不通，按顺序查：

  1. 地址与端口：后台填的 IP / 端口是否与配置一致；商品级配置是否覆盖了全局（商品级非空时优先于全局，最容易填错的就是这里）
  2. 监听地址：listen_host 设为 127.0.0.1 时只有本机能连；网站在另一台机器就要设成内网地址或 0.0.0.0
  3. 防火墙：Windows 防火墙入站规则是否放行该端口
  4. 口令：Bearer token 不一致，表现为鉴权失败
  5. 进程：APP 是否被关掉或重启后没拉起（联调时经常踩）

网站侧报「欲蓝服务器地址未配置」 ​

YulanConnector 拿不到可用地址。去后台「欲蓝服务器」填全局 IP 与端口，或在商品的「发货配置」里填商品级 IP / 端口。见 欲蓝财务魔方。

「欲蓝账号创建失败：…」 ​

APP 返回 ok:false，网站端抛 409，整单事务回滚（不会留下已付款但没账号的订单）。常见原因：

详情里的内容处理
账号不符合规则账号必须匹配 ^[A-Za-z0-9._-]{1,20}$——中文、空格、超 20 字符都会被拒
账号已存在Windows 里同名账号已建过，net user ... /add 会失败。清理旧账号或换账号生成规则
net 命令执行失败确认提权成功；中文系统组名不同可改 admin_group_name / rdp_group_name；必要时开 use_powershell
加入组失败远程桌面组 / 管理员组名称与系统语言不匹配
鉴权失败token 与网站后台不一致

建号命令是参数化执行（exec.Command("net", "user", 账号, 口令, "/add")），不经过 shell，配合账号白名单，不存在命令注入。

建号成功但角色不对 ​

角色由 APP 的 admin_products 决定，不由网站端指定：商品 ID 在列表里就建管理员（额外加入管理员组），否则按 default_role。改完配置要重启 APP。

网站端只负责把商品 ID 传过去，所以「后台里设了管理员但建出来是普通用户」时，去查 APP 配置里的商品 ID 是否写对。

日志里出现明文密码 ​

这是旧版本缺陷：掩码函数把 net user 账号 密码 /add 的第 3 个参数当成索引 2 脱敏，实际密码在索引 3（索引 0 是 net、1 是 user、2 是账号），导致密码被写进日志。Python 版与 Go 版首版都踩过，均已修正。

处理：升级到当前 Go 版 exe，并清理旧日志文件。日志本身已做 ACL 隔离，但明文口令一旦落盘仍应视为泄露，必要时轮换相关口令。

多个商品连不同服务器 ​

每个商品可以配独立的 IP / 端口 / 账号 / 口令 / 连接地址。做法是起第二个 APP 实例：不同端口、不同 token、不同 server_ip，再把商品级配置指向它。联调时验证过「第二实例 + 第二口令」全链路可用。

注意：两个实例别共用同一个端口和同一个日志文件目录。

安全底线 ​

APP 与网站之间是明文 HTTP，Bearer token 与建号口令都在里面传。所以：

  • 不要把 APP 暴露到公网；只在内网运行，或把 listen_host 设为 127.0.0.1
  • 配置样例里的 0.0.0.0 仅用于方便联调，上生产前收紧
  • 防火墙只放行网站服务器的 IP
  • 详见 Windows APP 与 常见问题 的安全章节
