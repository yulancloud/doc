09 安全规范与发布检查 ​

最后一篇讲怎么把前面写的功能安全发布。下面是一份可以逐项打勾的清单。

← 08 支付 / 发货扩展 ｜ 回到学习路线 →

一、系统已有的安全基线（别破坏） ​

机制实现你加功能时
SQL 注入Db::conn() 真预处理（EMULATE_PREPARES=false）一律 ? / :name 占位符，绝不拼 SQL
CSRFAdminAuth::require() → guardCsrf() 校验 Origin/Referer host+port后台写接口必须调 require()；公开写接口用限流 + 严格校验
存储型 XSS前台 textContent / U.esc()，后台 U.esc()拼 innerHTML 的所有外部文本都要转义
密钥商户密钥、服务器口令只写不读，不进 publicPayload()、不进日志新密钥类字段照此办理
限流RateLimiter::guard() 按 IP 哈希分桶，规则在 config.php每个公开写接口都要挂一条规则
安装锁config/installed.lock，已装后 /api/install 403升级时整个 config/ 不能删
敏感文件router.php 对 data/ config/ src/ .env *.sqlite 等一律 404新增敏感文件放到 Web 根之外
响应纯净四道闸保证 /api/* 只吐 JSON；Response 统一发安全头别 echo，一律走 Response::*
Host 伪造SHOP_BASE_URL 显式配置；SHOP_TRUSTED_ORIGINS 处理反代生产环境配好这两项
审计Audit::log() 写 admin_audit，不含密码 / 完整手机号后台写操作都要记一条

二、新增功能自检表 ​

逐条打勾，别凭「看起来正常」就上线：

#检查项判据
1所有 SQL 用占位符grep -rn 'SELECT.*\\$\|INSERT.*\\
#39; src/ 无字符串拼接
2所有输入过校验Validator::text/int/... 或显式白名单；长度有上限
3权限在后端后台接口有 AdminAuth::require()；越权直接调接口返回 401/403
4公开写有限流RateLimiter::guard('你的动作')，config.php 有对应规则
5输出转义接口文本用 textContent；拼 HTML 用 U.esc()
6响应格式只走 Response::ok/fail/json/plain，无裸 echo
7路由兜底新路径已加进 api/index.php 末尾 $known，方法错返回 405 而不是 404
8新装 + 升级schema.sql 与 migrate.php 都有；--dry-run 清单正确；旧库跑完迁移无报错
9幂等支付 / 回调 / 重复提交不会产生两条数据
10版本号改了 JS/CSS/HTML 已 bump 全站 ?v=
11密钥不落地grep -rn 'KEY\|password' public/ 找不到真实凭据；日志无明文口令
12回归测试tests/e2e.sh 等通过

三、发布流程 ​

text
① 备份 data/shop.sqlite 与整个 config/（含 .env、installed.lock）
      ↓
② 上传新版文件覆盖 —— 只覆盖程序文件，data/ 与整个 config/ 原样保留
      ↓
③ php bin/migrate.php --dry-run  →  php bin/migrate.php
      ↓
④ reload PHP-FPM（清 OPcache，若改了 PHP）
      ↓
⑤ Ctrl+F5 强刷前台与后台（或开无痕窗口），清 CDN 缓存
      ↓
⑥ curl /api/health 确认 build 版本号
      ↓
⑦ 走一遍验收清单 + tests/e2e.sh
      ↓
⑧ 记录本次定制补丁，供下次升级后重新套用

升级时 `config/` 整个目录都不能删

里面有 config/installed.lock 安装锁。删了会被判定「未安装」：/install 安装向导重新出现、全站 API 返回 503「站点尚未安装」，config/.env 的支付参数也一起丢失。恢复办法是从备份还原整个 config/，别在向导里重装（会覆盖店主账号）。详见 安装与升级 第四节。

从 Release 整目录覆盖时，style.css、SettingsService.php、config.php、各 HTML 都会被还原成官方版本。把自己的定制整理成一份补丁或单独记录，每次升级后重新套用，见 版本更新 与 主题定制设置。

四、测试脚本 ​

脚本覆盖
tests/e2e.sh基础下单 / 查询 / 后台流程
tests/e2e_payment.sh支付、回调、幂等、金额校验
tests/e2e_yulan.sh上游对接 / 云主机开通 / 工单归属隔离 / 旧库迁移 / CSRF（历史脚本名沿用）
tests/e2e_order.py、browser_check.py、site_check.sh订单与页面级检查

自测接口时记住三条：Content-Type: application/json、写操作带 Origin、后台接口带会话 Cookie。见 01 入门。

五、按错误码定位 ​

现象 / code先看哪一篇
not_installed 503安装锁丢了 → 安装与升级

rate_limited 429限流规则 → 03 基础 API
