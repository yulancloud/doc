功能自定义 · 学习路线

功能自定义 · 学习路线 ​

这是一套给「想在欲蓝财务上加功能」的人准备的线性教程：从把项目在本地跑起来，到读懂框架、加接口、建表、做出第一个完整功能，再到后台、前台、支付发货与安全发布。按顺序读，每页底部都有「上一步 / 下一步」。

只想换配色 / 改文案默认值，不用读这套 —— 去 主题定制设置 和 PHP 配置与文案默认值 就行。这里讲的是加新功能：新建表、写服务、注册接口、做后台页面、接前台交互。

学习路线 ​

步页面读完你能做到依赖

01入门与本地环境本地跑起来、跑通健康检查、做第一个可验证的改动PHP ≥ 8.1
02框架结构与请求生命周期说清一次请求从浏览器到数据库经过哪些层01
03基础 API读懂路由表、加一个只读接口和一个需登录的写接口02

05实战：从零做一个功能端到端做出「访客留言」：建表→服务→路由→后台→前台→测试03 + 04
06后台管理扩展加一个后台菜单页、复用设置表单、处理权限与审计05

建议的读法

01–04 是基础，一次读完；05 是实战，一定动手敲一遍；06–09 是进阶专题，用到哪篇查哪篇。每篇的示例代码都基于真实文件路径，可以直接对照着改。

开始之前：三条约定 ​

  1. 教程里所有路径都相对项目根目录（public/ 的上一级）。教程基于 v1.1.0（/api/health 的 build 为 20261116e）。
  2. 示例是教学用最小实现，用于讲清机制。上线前请按 09 安全规范 补齐校验与权限，别直接把示例粘到生产站。
  3. 动任何文件之前先备份 data/shop.sqlite 与整个 config/。升级时 config/ 整个目录都不能删，删了安装向导会重新出现，见 安装与升级 第四节。

一次典型的改动会碰哪些文件 ​

想加的东西要动的文件要跑迁移要 bump 版本号
一个只读接口public/api/index.php❌❌
一张新表 / 一个新字段database/schema.sql + bin/migrate.php✅❌
一段后台业务逻辑src/你的Service.php + public/api/index.php视情况❌
一个后台菜单页public/admin/index.html + admin/assets/views.js❌✅
一个前台页面 / 交互public/*.html + public/assets/*.js❌✅
一项可后台配置的参数src/SettingsService.php + 前后台表单❌✅
一条限流规则config/config.php 的 rate_limit❌❌

「bump 版本号」指把全站 HTML 里 ?v=20261116e 统一换成新值。JS / CSS 改了不 bump，浏览器和 CDN 会继续用旧文件，表现就是「我改了但没变化」。

通用流程：每个功能都走这 8 步 ​

text
① 备份 data/shop.sqlite 与 config/
      ↓
② 建表 / 加列：schema.sql（新装）+ migrate.php（旧库）
      ↓
③ 写服务类 src/XxxService.php（参数化查询、事务）
      ↓
④ 注册路由 public/api/index.php（含 $known 兜底数组）
      ↓
⑤ 后台：菜单按钮 + AdminViews 视图；前台：HTML + ShopAPI 调用
      ↓
⑥ 权限与限流：AdminAuth::require() / RateLimiter::guard()
      ↓
⑦ bump 全站 ?v= 版本号
      ↓
⑧ 测试：migrate --dry-run → curl 接口 → 页面强刷 → tests/e2e.sh

第 05 篇会把这 8 步完整走一遍，其余篇章分别展开其中一环。
