v2 插件主题教程（后台上传·从零到上架）

v2 插件主题教程（后台上传·从零到上架） ​

这篇教程从零开始，手把手做一个能在后台上传安装的主题和插件。每一步都给出可以直接复制的文件内容和命令，照着做完就能在商城里看到效果。 适用于 v1.2.0 及以上。主题与普通静态插件在 v1.2.0 就能用；自带 PHP 的功能插件需 ≥ v1.2.2（插件运行时）。老站或需要深度定制的仍可用 v1 插件主题教程（手动改 CSS），两者并存。

先搞清楚「插件」和「主题」在本系统里到底是什么

所谓扩展分两类，做主题和普通插件不需要懂 PHP

  • 主题 = 一份 CSS 变量覆盖文件（theme.css）。全站的颜色、字体、圆角都由 CSS 变量驱动，你只写要改的那几个变量，服务端会自动输出全站生效。
  • 普通插件 = 一堆静态文件（html / css / js / svg …）。后台上传后原样放到 public/plugins/<你的id>/，浏览器访问 /plugins/<id>/ 就能看到。
  • 功能插件（v1.2.2 起） = 上面再加一个 code/ 目录放自己的 PHP，可新增后台菜单、接口、注册校验等。这类需要有 PHP 基础，见 第八节。

做主题和普通静态插件，你需要的只有：文本编辑器 + 压缩软件。

一、先看效果：完整流程一览 ​

不管做主题还是插件，流程都是这 5 步，全程不到 10 分钟：

text
① 建一个文件夹        →   my-theme/  或  my-plugin/
② 写 plugin.json      →   告诉系统"我是谁、是什么类型"
③ 写主题 CSS 或插件文件 →   真正的内容
④ 压缩成 zip          →   顶层就是那个文件夹
⑤ 后台「主题与插件」上传 →   装完即启用，刷新前台看效果

全程唯一容易踩的坑

zip 的顶层必须刚好是一个文件夹，里面直接躺着 plugin.json。多套一层、少套一层、把当前目录整个压进去，都会导致上传失败或页面 404。第五节专门讲这个。

二、准备工具 ​

你要做的需要的工具说明
写 plugin.json / theme.css / HTML任意文本编辑器Windows 记事本、VS Code、Sublime 都行。别用 Word，它会存成富文本
压缩成 zip系统自带即可Windows 右键「压缩为 ZIP 文件」；macOS 右键「压缩」；Linux zip -r 命令
上传浏览器后台管理员账号登录
验证浏览器商城前台 + 管理员后台

不需要 PHP 环境、不需要数据库工具、不需要装任何软件。

三、从零做一个主题 ​

3.1 建目录结构 ​

在项目之外随便找个位置（比如桌面），建一个文件夹。文件夹名建议就用主题的 id，只能用小写字母、数字、连字符，2–48 位，且以字母或数字开头：

text
warm-orange/                ← 顶层文件夹，名字 = id
├── plugin.json             ← 必须有，主题的身份信息
├── theme.css               ← 必须有，你要覆盖的 CSS 变量
└── README.md               ← 可选，写给自己的说明

id 命名规则

id 是主题的全局唯一标识，上传、启用、卸载都靠它认。系统校验规则：^[a-z0-9][a-z0-9-]{1,47}$。 合法：warm-orange、ocean88、my-theme-2；非法：Warm Theme（大写/空格）、a（太短）、主题（非 ASCII）。

3.2 写 plugin.json（复制改一改即可） ​

在 warm-orange/ 里新建 plugin.json：

json
{
  "id": "warm-orange",
  "name": "暖橙主题",
  "version": "1.0.0",
  "author": "你的名字",
  "description": "把默认蓝换成暖橙色，亮色暗色两套都换",
  "type": "theme",
  "requires": ">=1.2.0"
}

每个字段的含义（必填项标了 ✅）：

字段必填你的主题怎么填说明
id✅warm-orange小写字母/数字/连字符，2–48 位，全局唯一。也是上传后的标识
name✅暖橙主题后台列表里显示的名字，随便起
version✅1.0.0你自己的版本号。同一个 id 再上传一次就算更新，改版本便于区分
type✅主题固定写 theme只能填 theme 或 plugin，填错装不上
author否你的名字展示用
description否一句话介绍展示用，最多 200 字
requires否>=1.2.0声明兼容的系统版本，仅作说明，不会强制拦截

两个新手常犯的错

  1. JSON 格式：键和值都要用英文双引号 "，不能用中文引号 ""，最后一个字段后面不能有逗号。写完整粘贴进编辑器，别手敲漏符号。
  2. type 别写成 theme （多个空格）或 Theme（大写）。系统会自动转小写去空格，但写规范点省事。

3.3 写 theme.css（核心） ​

这是主题真正的样子。只写你想覆盖的变量，没写的变量沿用系统默认。先给你一个「只换主色」的最小版本——这是 90% 的人想要的。

方案 A：只换品牌主色（推荐先从这个开始） ​

新建 theme.css，内容如下（把颜色和名字换成你自己的）：

css
/* 暖橙主题：只覆盖品牌主色，亮色 / 暗色两套 */
:root {
  --accent: #d2691e;        /* 主色：按钮、链接、选中态 */
  --accent-soft: #fbeadb;   /* 主色浅底：徽章、选中背景 */
  --accent-ink: #8a3d0b;    /* 压在浅底上的文字色 */
}
:root[data-theme=dark] {
  --accent: #f0a868;        /* 暗色下主色要更亮一点 */
  --accent-soft: #3a2718;
  --accent-ink: #ffcf9e;
}

三个变量必须成套改，含义是：

变量作用取色建议
--accent按钮、链接、选中态的主色选一个饱和的品牌色。亮色用深一点（#d2691e），暗色用亮一点（#f0a868），暗底上才看得清
--accent-soft主色的浅底色，用于徽章、选中背景亮色要很浅（接近白，带一点主色相），暗色要很深（接近黑，带一点主色相）
--accent-ink压在 --accent-soft 上的文字色用主色的更深版本，保证在浅底上看得清（对比度 ≥ 4.5:1）

不会配色？抄这个套路

把主色调成你的品牌色后：

  • 亮色 --accent-soft = 主色往白里兑（比如橙 #d2691e → 浅橙 #fbeadb）
  • 亮色 --accent-ink = 主色往黑里兑（#d2691e → #8a3d0b）
  • 暗色三兄弟同理，只是底色换成深色背景，主色本身调亮

在线工具搜「color palette generator」，输入品牌色就能拿到一套浅底/深文字。

方案 B：完整的变量模板（想大改时用） ​

想连文字、背景、圆角、阴影一起改，就把下面整份复制进 theme.css，逐个值改。这是系统 :root 的真实默认值，改哪行都行，不改的删掉即可。

css

  /* 文字：主标题 → 正文 → 次要 → 占位 */
  --ink-1: #12161c;
  --ink-2: #39434f;
  --ink-3: #6a7480;
  --ink-4: #98a1ac;
  /* 背景表面：页面底 → 卡片 → 纯白 → 分区 → 按下态 */
  --surface-0: #f5f6f8;
  --surface-1: #fafbfc;
  --surface-2: #ffffff;
  --surface-3: #f0f2f5;
  --surface-4: #e9ecf1;
  /* 描边三级 */
  --hair: rgba(18,22,28,.07);
  --hair-2: rgba(18,22,28,.11);
  --hair-3: rgba(18,22,28,.16);
  /* 品牌主色（三件套） */
  --accent: #d2691e;
  --accent-soft: #fbeadb;
  --accent-ink: #8a3d0b;
  /* 暖色点缀 */
  --warm: #a8703c;
  /* 字重 */
  --w-body: 400;
  --w-med: 500;
  --w-semi: 600;
  --w-strong: 700;
  /* 圆角 */
  --r-xs: 8px;
  --r-sm: 12px;
  --r-md: 16px;
  --r-lg: 22px;
  --r-xl: 30px;
  /* 布局 */
  --gutter: clamp(18px,4vw,52px);
  --max: 1260px;
  --head-h: 66px;
  /* 阴影三级 */
  --sh-1: 0 1px 2px rgba(18,22,28,.04), 0 6px 16px -12px rgba(18,22,28,.16);
  --sh-2: 0 2px 4px rgba(18,22,28,.04), 0 18px 40px -24px rgba(18,22,28,.28);

/* ===== 暗色（只覆盖要变的部分）===== */
:root[data-theme=dark] {
  --ink-1: #e8ebf0;
  --ink-2: #c2c8d2;
  --ink-3: #8d96a3;
  --ink-4: #6a7380;
  --surface-0: #11141a;
  --surface-1: #151a21;
  --surface-2: #1a1f27;
  --surface-3: #0d1015;

  --hair: rgba(232,235,240,.08);
  --hair-2: rgba(232,235,240,.12);
  --hair-3: rgba(232,235,240,.18);
  --accent: #f0a868;
  --accent-soft: #3a2718;
  --accent-ink: #ffcf9e;
  --w-body: 350;
  --w-med: 440;
  --w-semi: 540;
  --w-strong: 620;
}

亮色和暗色要成对改

任何颜色、字重、阴影类变量，都要在 :root 和 :root[data-theme=dark] 两处都改。只改亮色，用户一切到暗色就露馅。 圆角、间距、最大宽度、动效曲线只在 :root 写一次即可，暗色会继承。

暗色选择器不用纠结写法

系统自带暗色变量写在 :root[data-theme=dark]。你如果凭直觉写成 [data-theme=dark] 或 html[data-theme=dark]，特异性不够会被默认样式压过去，表现是「亮色换了、切暗色又变回默认蓝」。 服务端会自动把这两种写法提升成 :root[data-theme=dark]，所以怎么写都行；推荐直接写 :root[data-theme=dark]。

3.4 检查目录 ​

写完后应该是这样（用 tree 或直接打开文件夹看）：

text
warm-orange/
├── plugin.json      ✅ 已写，JSON 合法
└── theme.css        ✅ 已写，亮暗两套

到这一步，主题就做完了。跳到 第五节打包。

四、从零做一个插件 ​

主题只换外观，插件则是新增一个可以被访问的页面。做一个「欢迎页」插件，最终用户访问 /plugins/welcome/ 能看到它。

4.1 建目录结构 ​

text
welcome/                     ← 顶层文件夹，名字 = id
├── plugin.json              ← 必须有
├── files/                   ← 必须有，里面的文件会被原样安装
│   ├── index.html           ← 插件首页
│   └── style.css            ← 页面样式
└── INSTALL.md               ← 可选，安装说明

关键点：files/ 里的东西会被原样搬到 public/plugins/<id>/ 下。所以 files/index.html 最终就是 public/plugins/welcome/index.html，访问 /plugins/welcome/ 就能看到。

files/ 里可以放什么

只能是静态资源：html、css、js、svg、png、jpg、webp、json、md、txt、字体文件等。 不能放 .php、.sh、.exe 等任何脚本或可执行文件——系统会整包拒绝，详见第九节。

4.2 写 plugin.json ​

json
{
  "id": "welcome",
  "name": "欢迎页插件",
  "version": "1.0.0",
  "author": "你的名字",
  "description": "一个可以自定义文案的欢迎页，练手用",
  "type": "plugin",
  "entry": "index.html"
}

字段说明（主题里已讲过的不再重复）：

字段必填这里填什么说明
type✅插件固定写 plugin和主题的 theme 区分
entry否index.html入口文件名，默认就是 index.html。因为 files/index.html 会被装成首页，所以访问 /plugins/welcome/ 直接命中它

4.3 写 files/index.html ​

这是一个完整可用的页面，直接复制（它引用同目录的 style.css）：

html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>欢迎页插件</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <main class="card">
    <h1>你好，欢迎使用欲蓝财务 👋</h1>
    <p>这是一个插件新增的页面。你可以把它改成任何内容：</p>
    <ul>
      <li>公告板、使用说明、联系方式</li>
      <li>带一点 JavaScript 的小工具</li>
      <li>嵌入图片、SVG、字体</li>
    </ul>
    <p class="tip">改完 `files/` 里的文件，重新打包上传即可覆盖更新。</p>
  </main>
</body>
</html>

css

body {
  margin: 0;

4.5 写 INSTALL.md（可选但推荐） ​

markdown
# 欢迎页插件

在后台「系统 → 主题与插件」上传本 zip，安装后自动启用。

访问 `你的域名/plugins/welcome/` 查看效果。

需要系统 ≥ v1.1.0。

4.6 检查目录 ​

text
welcome/
├── plugin.json     ✅
├── files/
│   ├── index.html  ✅
│   └── style.css   ✅
└── INSTALL.md      ✅ 可选

插件也做完了。跳到 第五节打包。

五、打包：怎么压成合格的 zip ​

这是最容易出错的一步。记住一句话：zip 解开后，顶层必须刚好是一个文件夹，文件夹里直接是 plugin.json。

正确的结构（打开 zip 看到的样子）：

text
warm-orange.zip
└── warm-orange/          ← 有且只有一个顶层文件夹
    ├── plugin.json
    └── theme.css

错误的结构（都会被拒）：

text
❌ 没有顶层文件夹：        plugin.json 和 theme.css 直接躺在 zip 根部
❌ 多套一层：              warm-orange/warm-orange/plugin.json
❌ 把整个桌面压进去：       桌面/warm-orange/plugin.json（多了"桌面"这层）

命令行打包（推荐，最不容易错） ​

在项目之外的打包目录里，让顶层文件夹和 zip 平级：

bash
# Linux / macOS
cd 你的打包目录            # 里面只有 warm-orange/ 这一个文件夹
zip -r warm-orange-v1.0.0.zip warm-orange/

# 插件同理
zip -r welcome-v1.0.0.zip welcome/

打包完可以用 unzip -l warm-orange-v1.0.0.zip 看一眼，确认顶层就是 warm-orange/。

Windows 图形界面打包 ​

  1. 进入打包目录，选中 warm-orange 这个文件夹（不要进去选里面的文件）。
  2. 右键 → 「发送到」→ 「压缩(zipped)文件夹」，得到一个 warm-orange.zip。
  3. 双击打开 zip 检查：应该看到 warm-orange/ 一个文件夹，点进去才是 plugin.json。

macOS 图形界面打包 ​

选中 warm-orange 文件夹 → 右键 → 「压缩 "warm-orange"」，得到 warm-orange.zip，同样双击检查结构。

别用 rar / 7z

系统只认标准 .zip（deflate 或不压缩）。.rar、.7z、加密 zip、分卷压缩都装不上。

六、后台上传、启用、验证 ​

  1. 用管理员账号登录商城后台。
  2. 左侧菜单找到 「系统」 分组 → 点 「主题与插件」。
  3. 在「上传扩展包」区，点「选择 .zip 包」，选中刚做好的 zip。
  4. 点 「上传并安装」，等提示成功。
    • 主题：上传后自动设为当前主题，无需再点。
    • 插件：上传后自动启用。
  5. 打开商城前台看效果：
    • 主题：看主色是否变成你设的颜色；点顶栏的圆形明暗按钮切到暗色，再确认一遍。
    • 插件：浏览器打开 你的域名/plugins/welcome/，看到你写的欢迎页就对了。
  6. 如果没变化，按 Ctrl+F5 强刷一次（或开无痕窗口）清掉浏览器缓存。

为什么主题不用管浏览器缓存版本号？

v1 老办法要手动改全站的 ?v=20261116e 版本号，否则浏览器一直用旧 CSS。v2 的主题由 GET /api/theme.css 动态输出，服务端带 no-store，刷新即生效，不用碰任何版本号。这也是 v2 比 v1 省事的地方之一。

后台「主题与插件」页同一处还能看到已装的主题和插件列表，每行有对应操作按钮，下一节讲。

七、更新、停用、卸载 ​

想做什么怎么操作后果
更新主题/插件改好文件 → 用同一个 id 重新打包 → 后台再上传一次视为覆盖更新，新内容立即生效
切换主题在「已装主题」里点「设为当前」立即换上新主题
停用在对应行点「停用」插件：清掉 public/plugins/<id>/ 副本；主题：回退默认配色
重新启用在对应行点「启用」恢复插件副本 / 切回该主题
卸载在对应行点「卸载」，确认删掉原件和副本，完全还原，之后可重新上传

升级系统会不会丢主题/插件？

不会。原件存在 data/extensions/（Web 不可直接访问），public/ 下只是运行时副本。从 Release 整包升级时不覆盖 data/，所以你的扩展都在。升级完若前台没生效，到后台把主题重新「设为当前」或插件重新「启用」一次即可。

八、关于「功能插件」你需要知道的 ​

从 v1.2.2 起，系统引入了 插件运行时（PluginRuntime）：插件包可以自带 PHP 代码，功能真正由插件实现，系统主程序不再内置任何具体功能。这让"带后台菜单 / 接口"的插件成为可能，也意味着修功能只需更新插件、不用再升级系统。

运行时插件是怎么工作的 ​

一个"功能插件"比普通静态插件多一个 code/ 目录：

text
my-feature/
├── plugin.json          ← 加一个 "runtime": true
├── INSTALL.md
├── files/               ← 静态资源（可选）
│   └── index.html
└── code/                ← 服务端代码（存 data/，Web 不可直接访问）
    ├── plugin.php       ← 入口：返回 routes / hooks / assets 声明
    ├── routes.php       ← API 路由处理器
    └── assets/
        └── admin.js     ← 注入后台的脚本

code/plugin.php 用一份声明告诉系统要接入什么：

php
<?php
return [
  'routes' => [
    ['method'=>'GET', 'path'=>'/api/admin/plugin/my-feature/list', 'file'=>'routes.php', 'auth'=>'owner'],
    ['method'=>'POST','path'=>'/api/admin/plugin/my-feature/add',  'file'=>'routes.php', 'auth'=>'owner'],
  ],
  'hooks'  => [],                       // 如 'console.register' => 'hook.php'
  'assets' => ['admin' => ['assets/admin.js']],  // 注入点：login / console / admin
];
  • routes：插件自己的 API，<id> 可做路径参数；auth 支持 owner / admin / 空（公开），鉴权与 CSRF 由系统统一处理。
  • hooks：在固定流程点插入逻辑（如用户注册时校验邮箱验证码）。
  • assets：往登录页 / 用户中心 / 后台注入 JS/CSS；后台脚本用 window.AdminViews 注册页面、用事件委托加侧栏菜单。
  • 处理脚本通过系统注入的 $ctx（含 path/method/params）分发，用 Response::ok()/fail() 返回。

安全边界

  • 插件 PHP 只从 data/extensions/plugins/<id>/code/ 加载，Web 不能直接访问；禁止 .. 穿越与符号链接。
  • 只有 plugin.json 声明 "runtime": true 的包才允许带 code/；files/ 内出现 .php 等脚本仍整包拒绝。
  • 插件 API 只在声明表内匹配，未声明路径照旧 404；后台接口复用店主鉴权与 CSRF。
  • 运行时插件 = 完全信任作者的代码。只装你信得过的来源（官方插件经过验证）。

和老方式的关系

  • v1 纯静态插件（无 code/，只有 files/）照旧可用，适合加个静态页面。
  • v1.2.1 的"底座版"三款功能插件靠系统内置代码工作，在 v1.2.2 上请用它们的 v1.1 自包含版。
  • 想做一个全新复杂功能，用运行时插件比改核心更省事：升级不会丢、停用即失效、卸载即还原。

官方功能插件（v1.2.1 起，v1.1 自包含版需 v1.2.2） ​

插件装上后要点

九、安全限制：什么样的包会被拒 ​

后台对上传包做严格校验，做包时对照这份清单，能省掉绝大多数"为什么装不上"：

类别限制触发提示
大小zip ≤ 2 MB，解压后总量 ≤ 4 MB，单文件 ≤ 512 KB，最多 200 个文件"压缩包超过上限" / "文件过多"
主题 CSStheme.css ≤ 64 KB，plugin.json ≤ 16 KB"theme.css 超过 64 KB 上限" / "plugin.json 过大"
文件类型出现 .php / .jsp / .exe / .sh / .sql / .env / .zip 等脚本、可执行、配置、数据库后缀 → 整包拒绝"包内含有不允许的文件类型"
路径拒绝 ../ 路径穿越、绝对路径、盘符、隐藏文件（. 开头）、符号链接、控制字符"含有路径穿越" / 静默忽略隐藏文件
压缩格式只接受标准 zip（deflate / 不压缩）；拒绝 ZIP64、分卷、加密、带数据描述符"不支持分卷 / ZIP64 / 加密"
CSS 内容theme.css 禁 @import、javascript:、expression(、< 等"theme.css 含有不允许的内容"

危险后缀检查针对包里**所有**文件

即使某个 .php 放在不会被安装的角落（比如藏在 .backup/ 里），也会导致整包拒绝。打包前确认目录里没有多余文件。

十、排障清单 ​

现象最可能的原因怎么解决
上传报「包里找不到 plugin.json」zip 顶层结构错，或压根没写 plugin.json按第五节检查：plugin.json 必须在顶层文件夹里
报「包里含有不允许的文件类型」混进了 .php / .exe / .sql 等，或编辑器生成了 .DS_Store / Thumbs.db 之类删掉多余文件重新压
报「主题包里找不到 theme.css」主题包忘了放 theme.css，或文件名写成 Theme.css严格命名为小写 theme.css，放在顶层文件夹里
亮色变了、暗色没变只改了 :root，漏了 :root[data-theme=dark]暗色变量补上，或检查是否写在两个选择器里
设为主题但页面没变化浏览器缓存 / 没点「设为当前」Ctrl+F5 强刷；后台重新「设为当前」
主题上传后被自动覆盖回默认同 id 被别的包覆盖 / 主题被停用重新「设为当前」；确认没停用它
插件访问 /plugins/<id>/ 404① 运行目录没指向 public/；② files/ 多套了一层；③ id 填错看 部署总览；用 unzip -l 检查包结构；核对 plugin.json 的 id
