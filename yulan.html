魔方财务（对接上游）

魔方财务 · 对接上游 ​

自 v1.4.0 起，「魔方财务」重新定义为对接上游财务系统——像智简魔方财务的代理模式那样：添加上游 → 同步上游产品 → 加价销售 → 用户下单支付后，系统自动在上游创建订单并开通，把连接信息交付给用户。

一句话理解

你不用自己准备服务器建号端，只需对接一台上游财务系统，从它那里同步产品目录，设置自己的销售价，中间赚差价；开号的活交给上游完成。

版本说明

v1.3 及更早版本曾通过本地 Windows 建号端开通，v1.4 起已移除，不再需要部署 exe、不再有 8321 端口 / Token 等概念。从旧版升级后，未绑定上游的老商品仍按原有的全局配置行为运行（兼容回退），新配置请统一走上游对接。

一、整体由哪几块组成 ​

角色在哪配置干什么
商城网站你的 PHP + SQLite 站点（本系统）收单、维护上游与产品、加价销售、给用户展示交付信息
上游（finance 类型）后台「魔方财务 · 上游管理」记录上游接口地址、账号、API 密钥，是「去哪家进货」
上游产品上游管理里的产品列表从上游同步或手动录入的产品目录，供商城商品绑定

数据流一句话：

用户在商城付款 → 商城找到商品绑定的上游 + 上游产品 → 按上游配置调用其开放接口创建订单并开通 → 上游返回连接信息 → 商城把连接信息交付给用户。

二、后台「魔方财务 · 上游管理」 ​

左侧 魔方财务 · 上游管理 页面负责维护上游，可建多条、分别命名：

字段说明
名称起个好认的名字，如「上游A-魔方财务」，仅后台辨识用
类型finance=对接上游财务系统；cloud=魔方云 KVM（见魔方云）
接口地址上游的 API 地址，可填 IP 或域名，可含 https://
账号 / API 密钥上游提供的接口账号与密钥。密钥只写不读，保存后不回显
财务标识部分上游接口需要的 financial_id
账号类型代理商 agent / 普通
HTTPS是否通过 https 调用上游接口
状态启用 / 停用

测试连接：保存前可点「测试连接」，用当前配置请求上游，确认地址、账号、密钥、HTTPS 都填对了。

密钥只写不读

API 密钥保存后不会回显。再次编辑时留空 = 不修改；确认要清空可填 __CLEAR__。忘记密钥时重新填一遍覆盖即可。

三、同步上游产品与加价销售 ​

  1. 在上游列表点「产品」，进入该上游的产品目录。
  2. 点「同步产品」，系统会请求上游拉取产品列表；也支持手动新增 / 编辑。
  3. 每个产品可维护：名称、规格描述（CPU/内存/带宽等）、上游成本价、上架状态。

同步回来的产品，是下一步「商品绑定」的备选项。成本价来自上游，销售价在你自己的商城商品上设置——两者之差就是你的利润。

四、把商品绑定到上游产品 ​

  1. 左侧 商品管理 → 编辑 目标商品，类型选「魔方财务（对接上游）」。
  2. 在 发货配置 里找到 上游 下拉框，选中一条 finance 类型的上游。
  3. 再在 上游产品 下拉框里选中该产品（下拉随上游联动加载）。
  4. 保存。

支付后，系统按这个绑定关系自动在上游下单开通，并把交付信息写进订单。

新建商品要分两步

刚创建时还没有商品 ID，发货配置要先保存商品，再回来设。保存后在列表点「发货配置」即可。详见商品管理。

五、用户下单后拿到什么 ​

  1. 用户下单并完成支付（含 ¥0 免费直付）。
  2. 系统按商品绑定的上游与产品，调用上游接口创建订单并开通。
  3. 上游返回的连接信息写入交付内容，用户在订单 / 交付页即可查看。
  4. 开通失败会走事务回滚，不会留下「钱付了却没开通」的半成品订单。

六、演示与排障 ​

  • mock 模式：站点设置开启 upstream_mock 后，上游对接不联网，直接返回模拟的云主机与交付信息，方便测试与演示。
  • 开通失败、连接异常等排查，见 魔方财务使用教程 的故障速查与 后台与业务故障。
