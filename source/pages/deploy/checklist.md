# 上线自检清单

给**交付 / 接单 / 升级**用的逐项打勾表。按顺序走一遍，能挡住绝大多数"上线后才发现"的问题。每一条都给了可验证的判据，别凭"看起来正常"就签字。

## 一、动手前：先留退路

1. **备份数据库**：`cp data/shop.sqlite data/shop.sqlite.bak-$(date +%Y%m%d-%H%M)`，确认备份文件真的生成了且非空。
2. **备份原程序目录**（或打一个 zip），记录当前版本号。
3. **确认回滚方案**：知道备份在哪、怎么恢复、回滚后是否要重跑迁移。

> 覆盖文件时**只覆盖程序文件，整个 `config/` 与 `data/` 目录都不要删**。删了 `config/installed.lock` 会让站点回到未安装状态：`/install` 安装向导重新出现、全站 API 返回 503「站点尚未安装」，`config/.env` 的支付参数也会一起丢失。见 [安装与升级](/deploy/install) 第四节。

## 二、覆盖与迁移

4. 上传新版文件覆盖，确认 `public/admin/assets/app.js`、`views-v5.js` 等前端文件一起到位。
5. **执行迁移**（幂等，重复跑安全）：

   ```bash
   php bin/migrate.php
   ```

   它会补齐新列、放开 `CHECK` 约束，并自动修复旧库的子表外键损坏，见 [部署与迁移故障](/troubleshoot/deploy)。

6. **确认服务器跑的是新代码**：

   ```bash
   curl -sS https://你的域名/api/health
   ```

   返回的 `build` 必须是 `20261114i`。不是就说明文件没覆盖全、或 PHP-FPM/OPcache 还在跑旧代码（必要时重启 PHP-FPM）。

7. `Ctrl+F5` 强刷后台，或用无痕窗口打开，避开强缓存。

## 三、Web 服务器配置

8. **运行目录 = `public/`**（宝塔「网站目录」里的运行目录）。
9. **Nginx**：伪静态规则已粘贴**并保存**，规则里 `location /api/` 不要带 `^~`；PHP-FPM 解析规则存在。见 [Nginx 部署](/deploy/nginx)。
10. **Apache**：`public/.htaccess` 这个隐藏文件确实上传了，`mod_rewrite` 启用、`AllowOverride All`。见 [Apache 部署](/deploy/apache)。
11. 接口自检：`curl -i https://域名/api/health` 返回 **200 + JSON**，不是 PHP 源码、不是 404、不是 HTML 登录页。
12. 后台入口自检：`https://域名/admin/` 能打开登录页；访问 `/admin`（不带斜杠）应 301 补斜杠，见 [后台总览](/admin)。

## 四、安全核查（必做）

13. **源码不可下载**：访问 `https://域名/config/config.php`、`https://域名/data/shop.sqlite`、`https://域名/src/Db.php`，全部应 404。能下载就是运行目录写错了，属于**高危**，立即修。
14. `.gitignore` 生效，仓库里没有真实数据库 / `.env` / 备份 / 日志 / 上游密钥：

    ```bash
    git diff --cached --name-only | grep -E "shop\.sqlite|installed\.lock|\.bak-|\.log$"
    ```

15. 全站 **HTTPS**，混合内容（http 图片 / 网关）已清理；支付网关必须是 https 且以 `/submit.php` 结尾。
16. 上游 **API 密钥只在后台填写**，不写进代码 / 仓库 / 交付文档；对外接口均「只写不读」不回显。上游接口地址如非 https 已评估内网可达性。
17. 给客户的截图、演示、交付文档里，抹掉 `.env`、数据库、后台账号、上游 API 密钥、商户密钥。

## 六、交付物

27. 系统包（`yulan-shop.zip` 或对应 Release 资产）与版本号。
28. 文档站地址 **https://doc.yulancloud.us.ci/**，并告知客户部署章节在 [部署总览](/deploy)。
29. Release / 交付说明里写明：运行目录 `public/`、Nginx 伪静态规则、`php bin/migrate.php`、`/api/health` 的 build 号。
30. 管理员账号交接（走安全通道，别写在公开文档或聊天截图里）。
31. 明确**升级步骤**：覆盖 → 迁移 → 清缓存 → 验 build，写进交付说明，避免客户下次升级漏跑迁移。

## 最常漏的三件事

- **漏跑迁移** → 后台整片「加载失败」；旧库还可能触发 `__products_old` 外键损坏导致保存 500
- **运行目录 / 伪静态没保存** → 接口 404 或直接吐 PHP 源码
- **升级后不清缓存、不验 build** → 以为修好了，其实浏览器和服务器都还在跑旧代码

出问题时按 [故障排查总览](/troubleshoot) 的三步定位法走：验 `health` → 看 Network 响应体 → 确认迁移跑过。
