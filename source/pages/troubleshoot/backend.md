# 后台与业务故障

这一页按后台**真实返回的错误文案**逐条对照。弹窗只显示一句话时，用 `F12` → Network 看响应体里的 `code` 能精确定位。

## 登录与权限

| 文案 | 含义 / 处理 |
| --- | --- |
| `请先登录后台`（401） | 会话失效或未登录，重新登录。会话 Cookie 是 `HttpOnly + SameSite + Secure`，服务端只存 token 的 SHA-256 |
| `该操作仅限店主账号`（403） | 当前账号不是 `owner` 角色。敏感操作需要店主，见 [后台总览](/admin) |
| `密码或账号错误` / `用户名或密码错误` / `当前密码错误` | 账号密码不对，或改密码时原密码填错 |
| `该账号登录尝试过于频繁，请稍后再试` / `注册过于频繁` / `请求过于频繁` | 触发了频率限制，稍等再试 |

## 「请求来源不合法」403（CSRF）

**原因**：所有写操作（`POST` / `PUT` / `DELETE`）强制校验同源。没有 `Origin`（或 `Referer`）、或来源与站点 Host 不一致，一律拒绝。这是防跨站表单提交的正常行为，不是 bug。

**常见触发场景**：

- 用 `curl` / Postman / 脚本调后台接口，没带头 → 加 `-H "Origin: https://你的域名"`
- 反向代理把客户端的 `X-Forwarded-Host` 透传给了 PHP，导致同源判定被干扰 → 用 `$host` 而非客户端可控头
- 前后端域名不一致（例如后台挂在另一个域）→ 统一到同一域名

## 商品管理

| 文案 | 处理 |
| --- | --- |
| `商品编号只能用小写字母、数字和连字符（1-32 位）` | 编号改小写、去掉下划线与中文 |
| `SKU 只能用字母、数字、点、下划线、连字符` | SKU 白名单，去掉空格与中文 |
| `SKU 已被其他商品占用` / `商品编号已存在` | 换一个唯一值 |
| `请选择分类` / `所选分类不存在` | 先在分类管理里建好分类 |
| `划线价不能低于售价` | 划线价 ≥ 售价 |
| `图片地址只能是站内相对路径或 https 链接` | 不接受 `http://` 外链，避免混合内容 |
| `商品状态不合法` | 只能是上架 / 下架 / 售罄 |
| `商品类型只能是实体商品 / 虚拟商品 / 魔方财务 / 魔方云` | 提交值必须是 `physical` / `virtual` / `yulan` / `cloud` |
| `该商品已有订单记录，不能删除。请改为「下架」以保留历史订单。` | 有关联订单，只能下架；这是为了保护历史订单不丢失 |
| `库存不能小于 0` / `库存调整值不合法` | 调整值格式或结果越界 |

**添加 / 编辑商品没有「商品类型」下拉框？** 那是旧版前端文件没覆盖全，或浏览器缓存了旧的 `app.js`。强刷并确认 `public/admin/assets/app.js` 是新版，见 [商品管理](/admin/products)。

## 分类管理

| 文案 | 处理 |
| --- | --- |
| `分类编号只能用小写字母、数字和连字符` | 编号格式 |
| `「all」是保留字，请换一个编号` | `all` 是列表聚合用的保留 ID |
| `分类编号已存在` | 换唯一值 |
| `该分类下还有 N 件商品，请先移走或删除商品` | 先把商品移到别的分类 |

## 订单与发货

| 文案 | 处理 |
| --- | --- |
| `订单不能从「X」变为「Y」` | 状态流转不允许跳步，按顺序推进，见 [订单与发货](/admin/orders) |
| `订单状态已被其他人修改，请刷新后重试`（409） | 并发冲突：两个管理员同时改同一单，刷新后重试即可 |
| `运单号格式不正确` | 检查单号格式 |
| `订单不存在` / `发货记录不存在` | 记录已删或链接里的 ID 不对 |
| `发货内容不能超过 …` / `发货模板不能超过 4000 个字符` / `字段取值不能超过 500 个字符` | 内容超长，精简后再存 |
| `字段列表格式不正确` | 自定义发货字段结构不合法 |
| `商品类型只能是 virtual / physical / yulan / cloud` | 发货配置接口的类型值白名单（v1.4 起新增 cloud） |

**¥0 免费订单**：不走支付网关，直接置为已付款并触发发货（含上游开通），是验证整条链路最省事的方式。

**开通失败整单回滚**：上游开通返回失败时，接口直接 `exit`，未提交的事务自然回滚——不会留下"钱付了但没开通"的半成品订单。排查方向见 [魔方财务使用教程](/yulan-guide)。

## 评价与用户

| 文案 | 处理 |
| --- | --- |
| `XX格式不正确` / `XX不能为空` / `XX不能超过 N 个字符` | 评价内容校验，按提示改 |
| `评价不存在` / `用户不存在` | 记录已删 |
| `调整金额必须是整数（分，可为负）` | 余额以**分**为单位，且必须是整数 |
| `调整金额不能为 0` / `单次调整金额过大` | 金额越界 |
| `请填写调整原因（备注）` / `备注不能超过 200 个字符` | 备注必填且有限长 |
| `该用户余额不足，无法扣减`（409） | 扣减后不能为负 |

## 支付

| 文案 | 处理 |
| --- | --- |
| `网关地址无效（必须是 https 地址）` | 网关必须 https；明文 HTTP 一律拒绝，凭据也不允许塞进 URL |
| 跳到易支付官网首页而不是收银台 | 网关地址要填到 `/submit.php`，如 `https://pay.xxx.com/submit.php`。只填域名会打开官网首页 |
| `订单金额异常` / `订单金额异常，无法支付` | 订单金额与网关侧不一致，重新下单 |
| `发起支付时已超时` / `免费订单发起支付时已超时` | 支付请求超时，重试 |

**支付成功但订单没变已付款**，按这个顺序查：

1. 异步通知（`notify_url`）是否可达、是否被防火墙 / CDN 拦了；回调是 GET，成功必须返回**纯文本 `success`**
2. 验签是否通过：`hash_equals` 常量时间比较，签名算法取自服务端配置（不可被参数降级）
3. 回调的**状态 / 通道 / 金额**是否与订单完全相等，任一不符就拒绝
4. 是否重复通知：回调做了幂等，重复到达不会重复入账

这一套保证支付结果无法被伪造。配置字段见 [支付配置](/admin/payment)。

## 魔方财务 / 魔方云 / 工单（v1.4）

| 现象 | 处理 |
| --- | --- |
| 上游「测试连接」失败 | 核对接口地址、账号、API 密钥、HTTPS；确认上游服务可达 |
| 同步产品为空 | 检查上游接口返回格式；必要时手动录入产品 |
| 支付后未开通 | 检查上游余额、产品上架状态、接口错误；失败会整单回滚 |
| 后台看不到已配的密钥 | 「只写不读」：只显示「已配置」徽标；留空 = 不修改，填 `__CLEAR__` = 清除 |
| 商品没按预期开通 | 确认商品「发货配置」已绑定**上游 + 上游产品**并保存。见 [商品管理](/admin/products) |
| 用户看不到某台云主机 / 工单 | 归属隔离：只能看自己的，跨用户访问返回 404 属正常 |
| 想不接真实上游先演示 | 站点设置开启 **mock 模式**（`upstream_mock=1`），返回模拟数据 |

详见 [魔方财务使用教程](/yulan-guide)、[魔方云](/cloud)、[工单系统](/tickets)。
