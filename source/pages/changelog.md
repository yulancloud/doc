# 版本更新

这里记录每个版本相对上一版的变化与升级要点。升级前请先备份 `data/shop.sqlite` 与 `config/.env`。

## v1.2.3（插件界面修复版）

> 修复「功能插件装了却看不到界面」。商城系统版本，与 Windows APP 无关。

- **后台「主题与插件」页新增「功能插件自检」面板**：直接显示三个官方功能插件（SMTP 邮箱验证码 / 多管理员 / 登录页深色模式）是否已生效、系统构建号是否达标，并给出「未安装 / 部分缺失 / 已生效」三种明确状态与修复建议。
- **强制刷新前端缓存**：静态资源版本号升到 `v=20261118b`，解决浏览器 / CDN 缓存旧 JS 导致插件界面不注入的问题（这是「装了没界面」的常见原因）。
- **修正小白安装文档**：明确功能插件必须走后台上传 zip，手动解压 `files/` 只适用于静态插件。
- `/api/health` 的 `build` 仍为 `20261118a`（未变）。

> 升级：下载 `yulan-shop-v123.zip` 覆盖站点（保留 `config/` 与 `data/`）。升级后进后台「主题与插件」页看底部自检面板，三个插件都应显示「已生效」；若显示未安装，重新上传对应 v1.1 包。已生效仍看不到界面就强刷浏览器（Ctrl+F5）或清缓存。

## Windows APP v1.2.1（独立发布）

> 这是建号端 APP 的修复版本，与商城系统版本无关，商城端无需改动。

- **修复管理员账号被误判闪退**：旧版 Go exe 只认 UAC 提权令牌（`IsElevated`），域账户 / runas / 计划任务 / 关闭 UAC / 内置 Administrator 等场景下，明明是管理员账号却提示「不是管理员」并退出。新版同时接受「Administrators 组成员身份」，行为与 Python 版一致，管理员账号直接双击即可运行。
- 错误提示更明确；Python 参考实现版本号同步为 1.2.1。
- 升级：到 [APP 仓库 Release](https://github.com/yulancloud/yulancloudRubik-Windows/releases/tag/v1.2.1) 下载 `yulan_cube_app.exe` 覆盖即可，`/api/v1/health` 的 `version` 应为 `1.2.1`。详见 [Windows APP 故障](/troubleshoot/app)。

## v1.2.2

插件运行时版。静态资源版本号升到 `v=20261118a`（健康检查 `build` 为 `20261118a`）。

### 1）删除功能底座，功能全部由插件实现
- 新增 `PluginRuntime`：插件可自带 PHP 代码（存 `data/extensions/plugins/<id>/code/`，Web 不可直接访问），通过 `code/plugin.php` 声明 API 路由、注册钩子、注入前端脚本
- 移除系统内置的 `MailService.php`、`AdminAccountService.php`、`views-features.js` 及主程序里所有相关内置端点与菜单，主程序不再认识任何具体功能
- **以后修功能只更新插件**：逻辑都在插件包里，重传同名插件即覆盖更新，无需再升级系统

### 2）三款功能插件升级 v1.1（自包含，需系统 ≥ v1.2.2）
| 插件 | v1.1 变化 |
| --- | --- |
| SMTP 邮箱验证码注册 | 场景从「后台登录」改为**用户中心注册**：填邮箱 → 收验证码 → 校验通过才注册成功；只有后台白名单邮箱能收码并注册 |
| 多管理员账号 | 全部逻辑自带；修复「点新增管理员没弹窗」（抽屉缺 `is-on` 类） |
| 登录页深色模式 | 纯前端自包含，经运行时注入登录页脚本 |

### 3）兼容与安全
- v1 纯静态插件（无 `code/`）照旧可用；插件 PHP 仅从 `data/` 受控目录加载，禁止路径穿越与符号链接
- 插件 API 走统一声明路由，未声明路径照旧 404；后台插件接口复用店主鉴权与 CSRF 校验

> 升级：下载 `yulan-shop-v122.zip` 覆盖站点（保留 `config/` 与 `data/`），确认 `/api/health` 的 `build` 为 `20261118a`，再到插件市场下载三款 **v1.1** 插件重新上传安装。旧的 v1.0 功能插件在 v1.2.2 上不再提供功能。详见 [v2 插件主题教程](/developer/theme-v2)。

## v1.2.1

功能插件底座版。在 v1.2 基础上新增三个"装上就生效"的功能插件底座。系统包仍不含 Windows APP 的 exe（到 [Windows APP 仓库](https://github.com/yulancloud/yulancloudRubik-Windows/releases/tag/v1.2) 下载）。

### 1）三款功能插件（到插件市场按需安装）

三个功能**默认不开启**，到 [插件市场](https://yulancloud.us.ci/market/) 下载对应插件，在后台「主题与插件」上传安装后启用；不装不出现。

- **SMTP 邮箱验证码登录**（`smtp-login`）：后台多出「邮件服务器配置」，登录页新增「邮箱验证码」标签。纯 PHP SMTP 客户端，支持 STARTTLS / SSL / 免认证 relay；密码只写不读，验证码 5 分钟有效、最多 5 次尝试、用后即焚，白名单外邮箱混淆返回。需在「多账号管理」给管理员绑定邮箱。
- **登录页深色模式**（`login-dark-mode`）：登录页右上角出现明暗切换按钮，选择记在浏览器本地。纯前端。
- **多管理员账号**（`multi-admin`）：后台多出「多账号管理」，店主可新增第二个、第三个管理员，支持编辑 / 启停 / 重置密码 / 删除。一次性密码只显示一次，禁止删除当前账号与最后一个店主。

### 2）沿用 v1.2 能力

用户中心「控制台」改欲蓝魔方账号、后台主题/插件上传、干净安装默认 0 分类 0 商品，均保持不变。

::: warning 升级后必须强刷一次
静态资源版本号已升到 `v=20261116e`。升级后请 **Ctrl+F5** 强刷（或开无痕窗口）。
:::

### 健康检查

```bash
curl https://你的域名/api/health
```

`build` 应为 `20261116e`。若仍是旧值，说明服务器跑的还是旧代码或 CDN / 浏览器缓存未刷新。

## v1.2.0

控制台与扩展生态版。系统包仍不含 Windows APP 的 exe（到 [Windows APP 仓库](https://github.com/yulancloud/yulancloudRubik-Windows/releases/tag/v1.2) 下载）。

### 1）用户中心新增「控制台」
- 用户中心多出一个「控制台」标签，展示「我的欲蓝魔方商品」
- 进入商品详情可查看连接地址、账号等信息，并可**修改登录用户名 / 密码**
- 服务器不存明文口令：改号请求经管理员令牌交给 Windows APP 用系统账户强制修改
- 改号有独立限流 + 审计日志，口令全程不落库、不进日志明文
- 需配套升级 Windows APP 到 **v1.2**（新增 `/api/v1/update-user`）

### 2）后台上传主题 / 插件（v2 扩展机制）
- 后台「系统 → 主题与插件」上传 zip 即装，支持启用 / 停用 / 设为当前主题 / 卸载
- 主题只写 CSS 变量覆盖，服务端动态输出 `GET /api/theme.css`，升级覆盖 Release 也不丢；亮 / 暗两套自动提升选择器特异性
- 插件 `files/` 静态资源装到 `public/plugins/<id>/`，零侵入、不建表
- 纯 PHP 解析 ZIP，不依赖 ZipArchive 扩展；多重安全校验，危险包一律拒绝
- 更简单的制作方式见 [v2 插件主题教程（后台上传）](/developer/theme-v2)；旧的手动改 CSS 方式见 [v1 插件主题教程](/developer/theme)
- 也可到 [插件市场](https://yulancloud.us.ci/market/) 下载现成插件

### 3）干净安装默认 0 分类 / 0 商品
- 全新安装不再预置演示分类与商品；需要演示数据时 `php bin/init_db.php --with-demo` 显式开启

## v1.0.0

首个正式版本：包含「欲蓝财务魔方」产品类型（`yulan`）、商品级服务器配置、商品类型选择框，以及 64 项端到端测试。Windows 端建号 APP 独立维护在 yulancloudRubik-Windows 仓库。

## 升级步骤（通用）

```text
① 备份整个 data/ 与 config/ 目录（含 .env 与 installed.lock）
      ↓
② 上传新包覆盖程序文件（data/ 与整个 config/ 都不要删）
      ↓
③ php bin/migrate.php      ← 幂等，自动补列并修复旧库
      ↓
④ Ctrl+F5 清缓存
      ↓
⑤ curl /api/health 确认 build 版本号
```

::: warning
**`config/` 文件夹整个都不能删。** 里面有 `config/installed.lock` 安装锁，删掉后站点会被判定为「未安装」：`/install` 安装向导重新出现、全站 API 返回 503「站点尚未安装」，`config/.env` 里的站点地址与支付参数也一起丢失。只覆盖程序文件即可，升级包已排除这些文件。详见 [安装与升级](/deploy/install)。
:::

详见 [安装与升级](/deploy/install) 与 [部署与迁移故障](/troubleshoot/deploy)。
