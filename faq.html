常见问题

Q1：访问后台提示「加载失败，服务暂时不可用」？

通常是部署后没有执行数据库迁移，新列不存在导致接口报错。请运行 php bin/migrate.php，再 Ctrl+F5 清缓存后重试。迁移脚本幂等，可重复执行。

Q2：保存商品 / 设置提示「服务暂时不可用」？

多为旧数据库在迁移时外键子表未正确重建所致。最新迁移脚本已内置自动修复（repairChildTablesAfterRename），执行 php bin/migrate.php 即可自愈；若仍失败，检查 data/ 目录可写权限。

Q3：支付回调会被伪造吗？

不会。异步回调严格验签（hash_equals 常量时间比较、签名算法取自服务端配置不可降级），并校验状态 / 通道 / 金额完全相等与幂等，无法伪造支付成功。

Q4：是否存在 SQL 注入 / 命令注入？

后端全参数化查询（排序 / 状态走白名单）；Windows APP 建号使用参数化命令执行（不经过 shell），账号还做了白名单校验，无注入风险。

Q5：Windows APP 的通信安全吗？

APP 与商城服务端之间为明文 HTTP，请勿将 APP 暴露到公网，应部署在内网或将 listen_host 设为 127.0.0.1。令牌与建号口令仅在内部网络传输。

Q6：服务器口令会回显吗？

不会。商品级服务器口令「只写不读」，API 响应中根本不包含该字段；管理后台也仅显示「已配置」状态徽标。

Q7：升级后前端没变化？

浏览器强缓存所致。请 Ctrl+F5 强刷；系统对 JS / CSS / HTML 采用协商缓存，正常情况下改动后会自动拿到新版本。

Q8：文档站地址为什么是 yulancloud.github.io/doc？

GitHub Pages 免费方案只提供 <用户>.github.io/<仓库> 形式。若要 doc.yulancloud.github.io 这类子域名，需自行购买域名并在仓库 Settings → Pages 配置自定义域名。
