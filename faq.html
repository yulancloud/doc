常见问题

常见问题 ​

部署类 ​

Q1：Nginx 和 Apache 部署到底差在哪？ ​

只差要不要手填伪静态：

NginxApache
伪静态框必须粘一段规则留空，项目自带 public/.htaccess
额外开关PHP-FPM 解析规则mod_rewrite + AllowOverride All

其余（运行目录 public/、安装向导、php bin/migrate.php）完全一样。分别看 Nginx 部署 与 Apache 部署。

Q2：为什么接口返回一段 <?php 源码？ ​

Nginx 把 /api/index.php 当静态文件返回了。常见成因是把 /api/ 写成 location ^~ /api/ 并配 try_files——^~ 优先级高于 \.php 正则，PHP-FPM 根本没被调用。

  • 宝塔面板：用普通前缀 location /api/，不要加 ^~，见 Nginx 部署
  • 手写完整配置：/api/ 直接 fastcgi_pass，见仓库 deploy/nginx-root.conf

这也是配置与密钥泄露的高危点，务必修复。

Q3：后台打开空白、不跳登录页？ ​

访问的是 /admin 而不是 /admin/。不带结尾斜杠时浏览器会把相对资源算成 /assets/...，后台 JS 全部 404。伪静态 / .htaccess 里都带了 301 补斜杠规则，别删掉。见 后台总览。

Q4：Apache 下接口和后台全 404，但静态首页能开？ ​

.htaccess 没生效，按顺序查：① 隐藏文件是否真的上传了；② AllowOverride All；③ mod_rewrite 是否启用。见 Apache 部署。

Q5：访问后台提示「加载失败，服务暂时不可用」？ ​

部署后没有执行数据库迁移，新列不存在导致接口报错。运行 php bin/migrate.php，再 Ctrl+F5 清缓存后重试。迁移脚本幂等，可重复执行。见 安装与升级。

Q6：保存商品 / 设置提示「服务暂时不可用，请稍候再试」？ ​

多为旧数据库在迁移时外键子表未正确重建所致（SQLite ALTER TABLE RENAME 会把子表外键改写成 __products_old）。最新迁移脚本已内置自动修复（repairChildTablesAfterRename），执行 php bin/migrate.php 即可自愈；若仍失败，检查 data/ 目录可写权限。

Q7：点下单弹 404？ ​

伪静态没保存，或子目录部署时接口基址丢了前缀。见 Nginx 部署 的「常见故障」与 部署总览。

Q8：升级后前端没变化？ ​

浏览器强缓存所致。请 Ctrl+F5 强刷；系统对 JS / CSS / HTML 采用协商缓存，正常情况下改动后会自动拿到新版本。升级后务必跑一次迁移，见 安装与升级。

后台与业务 ​

Q9：商品类型下拉框在哪？有哪几种类型？ ​

添加 / 编辑商品表单里的「商品类型」下拉框：实体商品（人工发货）、虚拟商品（模板自动发货）、魔方财务（对接上游）（在上游下单开通）、魔方云（KVM 云服务器）（自动创建云主机）。v1.4 起新增 cloud 类型；编辑时不重新选择会保持原类型。见 商品管理。

Q10：魔方财务怎么开通？还要本地建号端吗？ ​

不用了。v1.4 起在后台「魔方财务 · 上游管理」添加上游 → 同步产品 → 商品发货配置绑定上游 + 上游产品，支付后即自动在上游开通。早期本地 Windows 建号端已移除。见 魔方财务使用教程。

Q11：支付网关地址怎么填？为什么跳到易支付首页？ ​

必须填到 /submit.php，如 https://pay.xxx.com/submit.php，且必须 https。只填域名会跳官网首页。见 支付配置。

Q12：¥0 免费商品能测试整条链路吗？ ​

能。售价为 0 的订单不走支付网关，直接置为已付款并触发发货逻辑（含上游开通），适合测试。见 订单与发货。

Q13：API 密钥 / 口令会回显吗？ ​

不会。上游 API 密钥、商户密钥等都「只写不读」，API 响应中根本不包含该字段；管理后台仅显示「已配置」状态徽标，留空表示不修改，填 __CLEAR__ 清除。

安全类 ​

Q14：支付回调会被伪造吗？ ​

不会。异步回调严格验签（hash_equals 常量时间比较、签名算法取自服务端配置不可降级），并校验状态 / 通道 / 金额完全相等与幂等，无法伪造支付成功。

Q15：是否存在 SQL 注入 / 命令注入 / 存储型 XSS？ ​

  • 后端全参数化查询（排序 / 状态走白名单），无 SQL 注入
  • 上游对接 HTTP 客户端限制超时、校验上游 JSON、错误给出可操作提示；API 密钥不落日志、不回显
  • 评价文本、商品名、工单正文等用户输入渲染前统一转义，无存储型 XSS
  • 工单与云主机用户侧强制按 user_id 过滤，跨用户访问返回 404

Q16：对接上游通信安全吗？ ​

上游地址建议填 https（后台有 HTTPS 开关）；API 密钥「只写不读」，不回显、不落日志。用户侧云主机 / 工单接口强制归属过滤，后台接口复用店主鉴权与 CSRF 同源校验。mock 模式下不接触真实上游。见 魔方财务（对接上游）。

Q17：运行目录写错有什么后果？ ​

把运行目录设成项目根目录，src/、config/、data/ 会变成可通过 URL 直接下载的文件——数据库、密钥、源码全泄露。必须是 public/。见 部署前准备。

前台显示与文案（v1.1） ​

Q18：后台改了首页文案 / 分类名，前台还是旧的？ ​

按这个顺序查：

  1. 浏览器缓存：Ctrl+F5 强刷或开无痕窗口。v1.1 把静态资源版本升到了 v=20261116e，不刷会继续跑旧 JS。
  2. 版本是否升到 v1.1：v1.0 及更早版本里，顶栏分类标签和首页「在售」区大标题是写死在 HTML 里的，后台怎么改都不生效。这是已修复的缺陷，见 版本更新。
  3. 打字动画：等动画播完（约 3 秒）再看。旧版 bug 是动画结束时会用写死的旧文案覆盖后台新值，v1.1 已改成停在后台设置上。
  4. 数据源：看页面 <html> 上的 data-api-source 属性，若为 static 说明没连上 API，走的是静态兜底数据，后台改动自然不生效。
  5. 改对了字段没有：「站点名称」只管顶栏品牌；想改首屏大字要改「首页主标题」，改导语要改「首页副标题」，改「在售」区大标题要改「商品区标题」。详见 站点设置与其他。

Q19：商品「已知不足」在哪里填？为什么前台不显示？ ​

后台「编辑商品」表单底部的「商品缺点 / 已知不足」多行框，每行一条。前台商品详情页会逐条展示；留空则整栏自动隐藏，这是正常行为。

填了但不显示，通常是：① 旧库没跑 php bin/migrate.php，products.flaws 列还不存在；② 浏览器缓存，需 Ctrl+F5。详见 商品管理 与 版本更新。

开发者 · 主题定制 ​

Q20：改了 style.css 的主题色，页面却没变化？ ​

按这个顺序查：

  1. 没 bump 版本号：所有 HTML 引用 style.css?v=20261116e，改了 CSS 不改 ?v=，浏览器 / CDN 会继续用旧文件。在项目根目录执行
    bash
    find public -name '*.html' -print0 | xargs -0 sed -i 's/v=20261116e/v=你的新版本号/g'
  2. 没强刷：Ctrl+F5 或开无痕窗口；前面挂了 Cloudflare 等 CDN 时还要清一层缓存。
  3. 只改了亮色：[data-theme=dark] 是独立一套，切到暗色会露出旧配色。颜色、字重、阴影相关变量要亮暗两处都改。
  4. 只改了 --accent：--accent-soft（浅底）与 --accent-ink（浅底上的文字）要配套改，否则徽章、按钮仍是旧色系或文字看不清。

变量清单、换色示例、主题切换原理见 主题定制设置。改 PHP 侧文案默认值不生效，见 PHP 配置与文案默认值。

Q21：自己加的接口 / 页面，升级后没了，或新接口报 404？ ​

  • 升级会覆盖：从 Release 整目录覆盖时 public/api/index.php、style.css、各 HTML 都会还原成官方版本。定制要整理成补丁，每次升级后重新套用，见 09 安全规范与发布检查。
  • 新接口 404：路由 case 没匹配（顺序被前面的正则抢了），或末尾 $known 数组没同步加 —— 方法写错时会返回 404 而不是 405。见 03 基础 API。
  • 只改了代码没改表：新装站点靠 database/schema.sql，旧库靠 bin/migrate.php，两边都要写，见 04 数据库与迁移。
  • 前台读不到数据：脚本没用 window.shopBoot() 注册，或改了 JS 没 bump ?v= 版本号，见 07 前台数据流。
